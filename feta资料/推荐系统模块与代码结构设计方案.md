## 1. 推荐系统模块设计（src/recommender.py）

### 1.1 设计原则

| 原则 | 说明 |
|---|---|
| **安全第一** | Level_4 高危不推内容，直接降级为求助热线 |
| **可解释** | 输出带 `similarity_score` / `final_score`，可回溯 |
| **可配置** | 权重、断路器阈值全进 `configs/config.yaml`，改参不改码 |
| **轻量** | 20 天 Demo，numpy 足够，无需 faiss |
| **可独立测试** | mock 向量 + 画像即可跑通，不依赖队友模块 |

### 1.2 输入 / 输出接口（Data Contract，已锁定）

**输入 A：`user_vector`**（`numpy.ndarray (384,)`）——由 3.2 基于 `embedding_prompt` 编码。

**输入 B：`profile_data`**（dict，由 3.1 吐出）：

```python
profile_data = {
    "risk_level": "Level_2_Moderate",   # Level_1_Low ~ Level_4_High
    "target_issue": "Academic_Stress",  # 8 大类压力源之一
    "strategy_weights": {               # 干预策略分类权重
        "relaxation": 0.35, "cognitive": 0.25,
        "healing": 0.25, "lifestyle": 0.15
    },
    "negative_rules": {                 # 负向黑名单
        "exclude_tags": ["fast_paced", "comparison"],
        "max_arousal_score": 0.4
    }
}
```

**输出：推荐结果 Dict**

```python
{
    "status": "SUCCESS",               # 或 "CIRCUIT_BREAKER_TRIGGERED"
    "risk_level": "Level_2_Moderate",
    "recommendations": [
        {"id": 102, "text": "...", "target_issue": "Academic_Stress",
         "similarity_score": 0.8241, "final_score": 0.8850},
        ...
    ]
}
```

### 1.3 五步核心逻辑

```
① 安全断路器   Level_4 高危 → 切断博文推荐，降级输出求助热线卡片
② 归因召回     target_issue 硬过滤；命中量 < top_k 软降级为全量库召回
③ 余弦相似度   user_vector vs Item Vector（加载时已归一化，点积即 cosine）
④ 加权+黑名单  剔除 exclude_tags / 超唤醒度内容，按公式精排
⑤ Top-K 截取   final_score 降序，截取前 K 条打包成 Feed
```

### 1.4 精排打分公式

$$\text{Score} = w_{\text{sim}} \cdot S_{\text{sim}} + w_{\text{boost}} \cdot S_{\text{boost}}$$

- `S_sim`：余弦相似度（用户向量 vs 干预项向量）
- `S_boost`：干预项正能量 boost 分（可按 `strategy_weights` 做轻调制）
- 默认 `w_sim=0.8, w_boost=0.2`（配置可调）

### 1.5 干预池数据结构（data/interventions.csv）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 唯一标识 |
| text | str | 疏导博文正文 |
| target_issue | str | 针对的压力源归因（8 大类之一） |
| boost_score | float | 正能量 boost 分 |
| tags | str | 逗号分隔内容标签（供 exclude_tags 黑名单） |
| arousal_score | float | 内容唤醒度（0~1，超阈值剔除） |
| strategy | str | 干预策略（relaxation/cognitive/healing/lifestyle） |
| embedding | str | 384 维向量（空格分隔，离线预计算） |

### 1.5.1 干预池来源：Sentiment140 四步构建流水线

`data/interventions.csv` 由 `scripts/build_intervention_pool.py` 从 Sentiment140（160 万条推文，取 label=4 正向约 80 万）离线构建，四步：

```
① 筛选预清洗   只取正向推文；去 @用户名 / URL / HTML 实体 / 重复标点；5~30 词长度过滤
② 正向疏导筛选 加权关键词打分（强疗愈词×2 + 普通正向词×1），剔除口语刷屏，取 Top-N
③ 归因打标     英文关键词规则 → 8 大压力源 + General（默认）；映射干预策略 4 类
④ 向量预计算   all-MiniLM-L6-v2 批量编码 384 维（缺依赖回退哈希基线），内联进 CSV
```

- **模型来源**：`models/all-MiniLM-L6-v2/`（本地目录，约 90MB，从 ModelScope 下载）。`Embedder` 自动优先加载本地路径，免联网、不依赖 HuggingFace（本机网络环境 HF 被代理拦截）；目录缺失时回退 HuggingFace 在线下载。

- **安全红线**：命中自杀/自伤词（`suicide`、`kill myself`、`self harm`…）硬性剔除，即使标签为正向也不进池。
- **匹配精度**：单词用词边界/集合交集（避免 `final→finally`、`fat→fate` 误匹配），短语用子串；匹配前归一化撇号/连字符（`don't→dont`、`self-care→self care`）。
- **配置**：`configs/config.yaml` 的 `pool_builder` 段控制规模/阈值/后端。
- 向量编码用 `f"{target_issue} {text}"`，与 classifier 的 `embedding_prompt` 同构，保证用户向量与干预向量同空间可检索。

> ⚠️ 内容质量说明：Sentiment140 是 2009 年英文推特，即便经过筛选，仍是「英文正向碎碎念」而非精挑的中文心理疏导文案，只作 Demo 知识库；正式版需换成人工策展的中文疏导内容库。

### 1.5.2 基线对比实验：哈希基线（TF-IDF 臂） vs MiniLM（BERT 臂）

`scripts/compare_backends.py`，9 条查询（覆盖 8 大压力源 + General）× 两组查询路径 × 两后端，Top-5 检索：

| 指标 | A·哈希 | **A·MiniLM** | B·哈希 | B·MiniLM |
|---|---|---|---|---|
| MRR@5 | 0.630 | **1.000** | 0.148 | 0.139 |
| Hit@5 | 42.2% | **97.8%** | 13.3% | 13.3% |
| Sim@5 | 0.860 | 0.565 | 0.093 | 0.305 |

- **A 组**：英文 `embedding_prompt`（契约规定的生产输入）；**B 组**：中文用户原文（对照）。
- **结论 1**：契约路径 + MiniLM 时检索近乎完美（MRR=1.0，8 类压力源 Top-1 全部命中正确归因）；哈希基线在 Family/Emotional_Health 等类完全失效。
- **结论 2**：中文原文直查英文池时**两后端都失效**（Hit@5≈13%）——证明契约里「classifier 吐英文 embedding_prompt 再编码」的设计是必要的，不能拿中文原文直接编码。
- **结论 3**：哈希基线的 Sim@5 虚高（0.86）但命中差，说明其相似度不可靠；MiniLM 相似度低而准。**Sim 分数只在同后端内可比，不可跨后端比较。**

```
feta/
├── app/
│   └── streamlit_app.py          # 王定祥：Web UI（调 pipeline.run()）
```

### 2.2 模块接口契约（并行开发不阻塞）

| 模块 | 负责人 | 输入 | 输出 |
|---|---|---|---|
| `preprocess.py` | 寇/李 | 原始文本 str | 清洗文本 str |
| `classifier.py` | 寇/李 | 清洗文本 | `profile_data` dict |
| `embedder.py` | 寇/李 | `embedding_prompt` | `user_vector (384,)` |
| `recommender.py` | **李鹏飞** | `user_vector` + `profile_data` | 推荐结果 dict |
| `pipeline.py` | **李鹏飞** | 原始文本 | 端到端结果 dict |
| `streamlit_app.py` | 王定祥 | 用户输入文本 | 页面渲染 |

```yaml
  top_k: 5
```

### 2.4 并行开发约定

1. **接口先行**：锁定 1.2 / 2.2 契约，各人按字段名写代码，谁先写完谁先联调。
2. **假数据驱动**：`recommender.py` 自带 mock 测试，`streamlit_app.py` 可先用假干预池画界面。
3. **统一环境**：uv 管理依赖（`uv sync` 一键还原锁文件环境，`uv run <脚本>` 直接跑），避免「我这能跑你那报错」。不用 uv 的队友可 `uv export --format requirements-txt > requirements.txt` 生成 pip 版清单。
4. **注释 + 日志**：每个函数写清输入输出，方便答辩归档。
